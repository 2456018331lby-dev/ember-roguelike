   142|## 当前建议的设计原则
   143|
   144|### Hades
   145|
   146|- 奖励要有诱惑力
   147|- 不是给“+10 数值”，而是给“玩法方向”
   148|
   149|### Slay the Spire
   150|
   151|- 风险收益必须清楚
   152|- 玩家需要知道自己为什么死
   153|
   154|### Vampire Survivors
   155|
   156|- 压力来自累积，而不是瞬间不透明暴毙
   157|
   158|### Dead Cells
   159|
   160|- 波次要有路径感和记忆点，而不是等差刷怪

## 7. 交接给后续 AI 的明确指令

- 先动 `web/src/game_core.mjs`，后动 `web/src/main.mjs`。
- 前端如果要美化，优先通过 `presentation.mjs` 扩展展示数据，不要把推导逻辑塞回 UI。
- 玩法数值调整要带测试；UI 调整要保持接口稳定。
- 任何新波次/新卡牌/新敌人都要补回归测试。
- 发布前要同步 `web -> docs -> android`，并确认 `npm test` 通过。
